# Prompt to continue the mobile app in a fresh session

Paste everything inside the block into a new Claude Code session opened in `/home/sedky02/my-pc/professional-projects/MoFin`. It authorizes **local commits only** (never a push) and tells the agent to keep working until the session ends.

````text
You are continuing the MoFin mobile app (Expo, iOS + Android) in /home/sedky02/my-pc/professional-projects/MoFin. Work autonomously until the session ends. I authorize LOCAL git commits for this work; you must never push.

READ FIRST (in this order)
1. docs/mobile/README.md        decisions, architecture, rules for every phase
2. docs/mobile/PROGRESS.md      status, decisions log, last handoff
3. the brief of the first unfinished phase: docs/mobile/phase-N-*.md
4. frontend/mobile/README.md and frontend/mobile/AGENTS.md (Expo's own guidance: use versioned Expo docs, `npx expo install`, never hand-edit ios/ or android/)
5. backend/CLAUDE.md before touching the backend

HOW TO WORK
1. Run `git status`. If earlier work is uncommitted (docs/mobile, frontend/mobile), commit it first in logical groups.
2. Build a task list from the remaining phases in PROGRESS.md (first unfinished phase onward; one task per step group of its brief). Keep it updated as you go.
3. Do the tasks in order. After EACH task:
   a. Run the checks: in frontend/mobile `npm run typecheck && npm run lint && npm test`; if the backend changed, in backend `npm test && npm run test:e2e && npm run lint`. For UI work, also check it in the browser through `npm run web` (Playwright screenshots at 390 and 820 px wide, light and dark). There is no phone or emulator here.
   b. If green, stage ONLY that task's files (never `git add -A`) and commit locally.
   c. Print the commit message and its short hash, then continue with the next task.
4. Commit messages: ONE line, conventional style `type(scope): message` with scope `mobile`, `api` or `docs`. No body, no trailers (no Co-Authored-By), no mention of AI or Claude, use the existing git identity, never pass --author.
5. Git limits: never push, never force, never amend/reset/rebase, no branches or worktrees. Don't commit `.env`, secrets, `.claude/` or `docs/demo-video/`. Don't edit `frontend/web` unless the phase brief says so.
6. At the end of each phase: tick it in docs/mobile/PROGRESS.md (status, decisions, what you could not verify) and commit that as `docs(mobile): ...`.

KEEP GOING; STOP ONLY FOR
- a step marked GATE in a brief (ask me first),
- a new BACKEND dependency or database schema change that a brief does not already approve (`jose` is approved; the Apple/appleId work is deferred and out of scope),
- a manual step only I can do (deploying the backend, EAS login, Google/Apple consoles, testing on a device): write it into the PROGRESS.md handoff, skip to the next task that is not blocked, and carry on,
- an error you cannot resolve after 2-3 genuine attempts: record it and move on.
Make routine decisions yourself, following the brief's defaults, and log them in PROGRESS.md.

QUALITY RULES
- Money, decimals and dates: use the copied src/core helpers; never reimplement formatting or arithmetic. The web app is the reference for behaviour and copy.
- Follow docs/mobile/README.md "Rules for every phase" and frontend/mobile/README.md conventions (routes only in src/app; Testing Library 14 is async; theme is generated by `npm run theme:sync`).
- Phases 3 and 4 (token verification, sessions) are meant for Opus. If you are running on Sonnet, still do them, with extra tests, and flag them in PROGRESS.md for review.
- Use the installed skills where they fit (Expo plugin, React Native performance, animation, ux-audit, tdd) and verify against the real SDK 58 docs before using an Expo or React Native API you are unsure about.

WHEN THE SESSION IS ENDING (or your context is nearly full)
Write a "Handoff" section in docs/mobile/PROGRESS.md: what is done, what is next, what is blocked, and the exact manual steps I must do. Commit it as `docs(mobile): ...`, then give me a short summary: the list of commits (hash + message) and anything I need to do.
````
